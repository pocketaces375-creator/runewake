## Orchestration era (witnessed in this chat, 2026-08-29 → 08-31)

1. **Card border direction: carved stone** → 7 generated candidates → **Root-Bound (option 5) locked by Trikzos**.
2. **Band thickness is computed, never authored:** generative models ignore "thin band" instructions (~16% delivered vs 5% asked), so borders are **9-sliced** — detect the painted window (`tools/detect_v2.py`), slice 4 corners + 4 edges (`tools/nineslice.py`), rebuild at `band_px = round(card_width × 0.07)`; corners at band_px square never stretched, edges stretch along their length only. **7% band locked** after in-hand fan tests at realistic size.
3. **Name auto-fit is a hard rule** (Trikzos rejected a build over name overflow): safe zone = art window inset by `max(6% card width, 10px @236w)` per side; base 24px @ 236px card width scaling linearly; shrink to floor 62% of base; then two balanced-by-characters lines starting at base−2 down to hard minimum 12 (8 on minis); no glyph below 8px, ellipsis beyond; the stat rail is excluded from the safe zone (reserve rail first, fit name into the remainder); text never touches border or badges at any size. Reference impl `tools/namefit.py`; spec `client/content/art/border/rootbound_9slice.json`. Cost rune moved **top-right** (Root-Bound's corner motif owns top-left).
4. **Trikzos' eyes are the release gate for visual work.** Adopted after production agents twice marked visually broken work DONE with green gates: (a) wide capture byte-identical to standard + meta rewritten 1999×932→1152×648 — the gate read its expected dims from the artifact under test and passed itself; (b) NinePatchRect with raw texture margins (148–197px) on ~88px cards — Godot draws patch margins 1:1 in screen pixels, so corners consumed entire card faces. Standing countermeasures now in gates/AGENTS.md: fail on byte-identical capture pairs; fail wide metas without wide dims; fail occupied slots whose center matches their own border; "describe what a player would see" before any visual DONE; re-verify from zero after changing rendering approach mid-task.
5. **First-player advantage is structural — do NOT nerf classes against current matrix data.** SIMGATE-1 failed with 25 violations, but mirrors show P0 winning ~62.5% (Warrior 66.5 / Cleric 68 / Ranger 68 / Thief 63.5 / Mage 58 / Necro 57.5 / Runesmith 56), largest for fast classes, games ending turns 7–8 → tempo bias inflating aggro numbers. Sequence: verify the sim's roster is even real (its class names don't match content/classes.json), fix P1 compensation via mirror-harness variants (P1 +1 attunement / 6th card / both / P0 ramp delay), re-run gate, THEN tune classes. Sim tasks REPORT ONLY; numbers are Fable's to move.
